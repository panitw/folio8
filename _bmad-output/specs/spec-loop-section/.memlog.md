topic: Loop Start / Loop End elements that repeat a slab of the content band once per item of a bound array
updated: 2026-09-20T15:19
---

- (direction) Owner asks for two new elements, Loop Start and Loop End, shaped like the Section Break: Loop Start binds to an array, every element between the two markers repeats once per item and binds to that item's fields.
- (direction) Owner explicitly asked for prior-art research on whether the paired-marker pattern is sound versus how other reporting products do it.
- (note) Codebase fact: folio8 content is absolute-positioned, one tall column per designed page, four window rules; 'nothing reflows because a neighbour grew' with exactly two exceptions today, the section break's below-line section and a Page Break off designed page, each moving as a rigid block (docs/folio-format.md Pagination).
- (note) Codebase fact: the only repeating construct today is the table element, binding a collection path suffixed [] with an 'as' row alias; row scope never shadows the document root and params is reserved.
- (note) Codebase fact: Section Break is a flat band key (sectionBreak/sectionBreakAnchor) with a geometric membership rule and a straddle refusal SECTION_BREAK_STRADDLED, at most one per designed page. That is the precedent a marker pair would follow.
- (note) Research: visual report designers overwhelmingly model repetition as a CONTAINER, not a marker pair - banded detail bands (Crystal, JasperReports, FastReport, Stimulsoft, DevExpress, Telerik), the SSRS List data region (free-form absolute layout inside, repeating per row or group), and the AEM/LiveCycle repeating subform with 'Repeat Subform For Each Data Item'.
- (note) Research: paired start/end markers are the FLOW-document idiom - docxtemplater {#loop}...{/loop}, Carbone, Docmosis, Handlebars blocks. They work there because the document is a linear sequence of paragraphs, so 'between the markers' needs no geometric rule.
- (note) Research verdict: the pattern is sound for folio8 because the Section Break already proved the geometric membership and straddle-refusal rule in a 2-D band, but the marker pair is the minority form and its costs land on nesting and scope.
- (decision) Owner chose the REPEATING CONTAINER shape over the Loop Start / Loop End marker pair, after the prior-art research: one new containing element type, children at container-relative coordinates, the SSRS List / AEM repeating-subform model.
- (decision) Owner chose nested loops in scope from the start (invoice -> line items -> per-line charges), which requires an alias scope stack and containment rules.
- (decision) Owner chose variable-height iterations: an iteration grows with its data, so a table may live inside the loop and push that iteration taller.
- (decision) Owner chose the empty-array behaviour to be the author's choice, defaulting to reserved: the slab stays as declared empty space unless the author opts into collapsing.
- (constraint) Element type is closed set #1 in the format (text/image/table/line/rect/barcode/qrcode). Adding a type is therefore a MAJOR change by the format's own compatibility rules, 4.1 -> 5.0, and older readers refuse such a document outright. This is the concrete price of the container shape and it must be stated in the contract.
- (decision) The declared loop height is a FLOOR on each iteration, not a fixed height - the same idiom as table headerHeight and table minHeight. An iteration is max(declared height, measured extent of that iteration's content).
- (decision) Children's x and y are relative to the loop's top-left, generalising the format's existing rule that an element's x and y are relative to its band's top-left; a band and a loop are both containers.
- (decision) Iterations split across a page under the four window rules by default, consistent with folio8's own defaults, with an opt-in per-iteration keep-together; the aggregate-too-tall case takes the existing clip-with-warning answer rather than refusing.
- (decision) Aliases never shadow: a nested loop whose collides with an enclosing loop's or table's alias is a load error, matching the existing rule that a row never shadows the document root. params, page and pages stay reserved.
- (decision) A keepTogether tag inside a loop is scoped to one iteration; a tag with members both inside and outside a loop is a load error.
- (decision) Designer keeps the owner's mental model visually: the container is drawn with a LOOP START bar at its top edge and a LOOP END bar at its bottom edge, carrying the bind path and alias, even though the file holds one element.
- (assumption) Nesting depth capped at 3 levels (invoice -> line -> charge), a load error beyond, chosen for a bound rather than from a stated requirement.
- (constraint) Clarifying the entry above: the new element type is named "loop", and it is adding a member to closed set #1 (element type) that forces the MAJOR bump to 5.0.
- (decision) Clarifying the alias entry above: the field is the loop element "as" key, and a nested loop whose "as" collides with an enclosing loop or table alias is a load error.

No wrapper-only content was dropped; the one transformation is the owner's own decision to take the container shape over the marker pair, recorded in the memlog.
- (decision) Owner accepts the MAJOR format bump to 5.0 for the loop element type. That open question is closed.
- (decision) Owner: a nested loop MAY bind a root-relative collection, and the format gains an explicit root notation for it - a path may begin with the segment $ meaning the document root, spelled $.field.
- (note) Codebase fact justifying the root notation: bind.Scope resolves by first-path-segment equality in the order params, row alias, data root (folio-go/internal/bind/scope.go WithRow). So a root field whose name equals a live alias is UNREACHABLE today. With up to three live aliases in a nested loop that trap gets much worse, and $. is the escape hatch that makes the root reachable regardless.
- (decision) The $ root notation is OPTIONAL everywhere a path is legal (text expressions, visibleIf, column binds, table and loop binds, footerOf), never required, so no existing template changes meaning. Bare $ with no dot is a located error - it is a namespace, not a value - matching the existing bare-row-alias error. $ can be shadowed by nothing, and no alias may be named $.
- (decision) A document using the $ root notation requires format 5.0, the same MAJOR as the loop element, because an older reader's expression parser fails on the $ character.
- (decision) An iteration too tall for a whole content window under per-iteration keep-together is CLIPPED on a page of its own with a warning naming the loop and the iteration index, and the render SUCCEEDS - matching the clipped table row and the keepTogether group too tall only in aggregate, because the height came from the data. A single child by itself taller than a window remains a hard error naming that child, unchanged.
- (decision) Owner: the Loop palette entry stays armed and a band may hold several loops, unlike the Section Break entry which disables after one.
- (decision) Sibling loops may not overlap: two loops whose declared boxes intersect are a load error naming both. A loop's growth pushes every later sibling loop down as ordinary content below it.
